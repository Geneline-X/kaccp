# Deployment

How to run KACCP in production, including a configuration that uses **no proprietary services at
all**.

---

## 1. Requirements

| | Minimum |
|---|---|
| Node.js | 20+ |
| PostgreSQL | 15+ |
| Disk | Audio storage — budget ~2 MB per minute of 16 kHz mono WAV |

Nothing else is required. Everything below the fully-open configuration is optional.

---

## 2. The fully open deployment

This is the configuration to use if you want zero dependency on any commercial service — and the
one that substantiates the platform-independence claim.

```bash
# .env
DATABASE_URL="postgresql://kaccp:password@localhost:5432/kaccp"
JWT_SECRET="$(openssl rand -base64 32)"
NEXT_PUBLIC_APP_URL="https://your-domain"

STORAGE_PROVIDER="local"
LOCAL_STORAGE_ROOT="/var/lib/kaccp/audio"

MASTER_ADMIN_EMAIL="admin@your-domain"
MASTER_ADMIN_PASSWORD="change-me"
```

```bash
npm ci
npx prisma migrate deploy
npm run seed:admin
npm run build
npm start
```

What you get: PostgreSQL for data, the local filesystem for audio, manual transcription. No cloud
storage account, no AI provider, no third-party identity service. Every other integration in
`.env.example` is opt-in.

**If you back up nothing else, back up two things:** the database, and the audio directory.

---

## 3. Migrations

```bash
npx prisma migrate deploy     # production — applies pending migrations, never resets
```

Never run `prisma migrate dev` or `prisma migrate reset` against production; both can drop data.

Migrations are additive and nullable wherever possible, so they can be applied to a live database
without downtime.

---

## 4. Database connections — read this before you scale

Each API route deploys as its own serverless process on most hosts, so the connection budget is:

```
concurrent routes  ×  connection_limit  ×  instances
```

One dashboard load touches about four routes. With Prisma's default pool of `num_cpus*2+1`, that
is dozens of connections against a managed database that may allow only ~25 — which fails as
`P2037: remaining connection slots are reserved for roles with the SUPERUSER attribute`, and takes
down login along with everything else.

KACCP therefore defaults `connection_limit` to **1** and caches the Prisma client on `globalThis`.

| Setup | Recommended |
|---|---|
| Single server, long-running process | `DB_CONNECTION_LIMIT=10` |
| Serverless, no pooler | `DB_CONNECTION_LIMIT=1` (the default) |
| **Behind PgBouncer / a managed connection pool** | `DB_CONNECTION_LIMIT=10`, add `&pgbouncer=true` to `DATABASE_URL` |

**A server-side pooler is the durable fix.** Most managed Postgres providers offer one free. Use
transaction mode.

## 5. Storage

### Local filesystem

```bash
STORAGE_PROVIDER="local"
LOCAL_STORAGE_ROOT="/var/lib/kaccp/audio"
```

The directory must be writable by the app and **must not be web-served**. Audio is delivered only
through signed URLs generated by the API.

### Cloud object storage

```bash
STORAGE_PROVIDER="gcs"
GCS_BUCKET="your-bucket"
GCS_SERVICE_ACCOUNT_JSON='{"type":"service_account", ...}'
```

The bucket must be **private**. KACCP issues signed URLs (1 hour read, 15 minutes write); a public
bucket would bypass that and expose contributor voice data.

### Adding S3 or MinIO

Implement `StorageProvider` (`src/lib/infra/storage/provider.ts`) in one new file and register it
in `index.ts`. Nothing outside that directory needs to change.

## 6. Security checklist

- [ ] `JWT_SECRET` is long, random, and not the example value
- [ ] TLS terminates in front of the app; no plain HTTP
- [ ] Object storage bucket is **private**
- [ ] `LOCAL_STORAGE_ROOT` is outside the web root
- [ ] Database is not reachable from the public internet
- [ ] `.env` is not committed — it is gitignored; verify with `git ls-files | grep env`
- [ ] Admin password changed after first login
- [ ] Backups configured for **both** database and audio, and a restore has been tested

---

## 7. Operating

**Health.** `/api/v2/languages` returns 200 when the app and database are both reachable.

**Watch for:** `P2037` (connection exhaustion — see §4), storage errors during upload, and queue
depth. A pending-transcription queue that only grows means you need more transcribers, not more
servers.

**Scaling order.** Database connections bind first, then storage throughput, then CPU. Add a
connection pooler before adding app instances.
